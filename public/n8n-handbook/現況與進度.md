# 現況與進度

這篇寫給處內剛加入數位轉型組、還在熟悉 n8n 的同事看，說明現在進度到哪、為什麼還不能像 UiPath 一樣馬上派上用場，以及接下來會怎麼展開。

---

## n8n 跟 UiPath 最大的不同：沒有「錄製」

先講一個心理準備，這是接下來所有進度安排的原因。

**UiPath 你熟悉的做法**：打開 Recorder，在畫面上點一次你平常做的操作，UiPath 全部錄下來變成流程步驟。你不太需要知道「為什麼」，跟著錄、微調一下就能動。這就像用相機把你做的事錄下來，之後重播一次。

**n8n 沒有錄製這個功能**。你要自己想清楚「這件事分成哪幾個步驟、每個步驟要用哪個節點、資料怎麼從這一步流到下一步」，再一塊一塊把節點串起來。比較像玩樂高——沒有人幫你把成品拍下來重播，你要看懂說明書、知道每一塊積木的用途，自己組出你要的東西。

這代表 n8n 前期需要花一點時間理解「節點、資料、邏輯」這幾個概念，不像 UiPath 錄一錄就有東西動。但換來的好處：

- **錄製的流程很怕畫面改版**——這是很多人用 RPA 最痛的地方，系統換個按鈕位置整組流程就壞了。n8n 用節點描述「要做什麼」而不是「點哪個座標」，相對沒那麼脆弱
- **n8n 不是只能對著一個畫面錄**，一個流程裡可以同時處理 Excel、呼叫網頁、寫資料庫、寄信，UiPath 也做得到，但 n8n 因為本來就是「串接不同系統」設計的工具，這件事做起來更直覺

所以現階段的目標不是「馬上做出一個完整流程」，而是**先把「節點、資料、邏輯」這幾個基本概念練熟**，這是之後不管接上什麼系統都用得到的基本功，比急著做出成品更重要。

---

## 現在在哪個階段

| 項目 | 狀態 |
|---|---|
| Tailscale 連線設定、n8n 帳號 | ✅ 已完成 |
| 熟悉平台基本操作（節點、觸發、資料怎麼流動） | 🔄 進行中 |
| IT 開通：檔案要能進出的儲存空間 | ⏳ 等待中 |
| IT 開通：連到內部系統的網路 | ⏳ 等待中 |
| 用真實情境（Excel 處理、網頁登入）完整跑通一次 | ⏳ 待 IT 開通後 |
| 第一個正式流程上線 | ⏳ 之後規劃 |

**現在的目標，就是把第二項做熟**，其他項目卡在 IT 對接，不是你這邊能加速的部分。

---

## 為什麼現在還不能像 RPA 一樣馬上用

UiPath 主要跑在你自己的電腦上——你的螢幕、你電腦裡的檔案，Recorder 都直接看得到，裝好軟體就能開始錄，不太需要額外申請什麼。

n8n 不一樣，它跑在一台大家共用的伺服器上，**不是**在你自己的電腦裡。它要摸到公司內部的檔案、要連到要自動化的內部系統，這些「路」都要 IT 事先幫忙開通，不是裝好軟體就自動有的。

目前這兩件事（檔案儲存空間、內部系統的網路連線）都還在跟 IT 對接，還沒開通，所以拿真實情境做的範例（處理 Excel、登入系統）現在會卡在最後一步——**這是預期中的事，不是你操作錯了**，詳細技術原因記錄在[探測 n8n 主機環境](範例%20-%20探測%20n8n%20主機環境.md)這篇。

---

## 現在可以做什麼

不用等 IT，現在就能練的：

1. [新手指南](新手指南%20-%20第一次使用%20n8n.md)——認識介面，建立第一個 workflow
2. [骨架練習（免外部環境）](範例%20-%20骨架練習（免外部環境）.md)——完全不連外部網路、不碰檔案系統，練節點怎麼組合、資料怎麼流動、失敗了怎麼看

這兩篇練熟之後，等 IT 那邊開通了，[Excel 處理](範例%20-%20Excel%20處理（取代%20VBA）.md)、[Playwright 網頁登入](範例%20-%20Playwright%20網頁登入.md)這兩篇比較貼近真實情境的範例就能整套跑完，而且用的是同一套節點邏輯，不用重新學。

---

## 之後怎麼逐步展開

不是一次到位，是分階段：

1. **現在**：熟悉平台操作，跟 IT 對接檔案/網路
2. **IT 開通後**：把 Excel、Playwright 範例真的跑完一次，確認整套機制沒問題
3. **挑一個簡單、風險低的實際業務流程**，照[開發規範（RPA 對照版）](開發規範%20-%20RPA%20對照版.md)的骨架試做第一支
4. **累積幾支流程之後**，共用元件、資料表這些機制才有實際打磨的機會，逐步擴大範圍

這份進度會持續更新，跟 IT 有新進展、或練習階段有新發現，都會回來改這篇。
