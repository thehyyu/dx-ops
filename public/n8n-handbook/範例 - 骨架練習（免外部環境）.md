# 範例：骨架練習（免外部環境）

*前提：已讀過[[新手指南 - 第一次使用 n8n]]，知道 workflow、node、trigger 是什麼。*

*n8n 介面預設是英文，這篇每個用到的按鈕/節點名稱都附繁體中文對照，照著英文字找就對了。*

---

## 為什麼需要這篇

[[範例 - Excel 處理（取代 VBA）]]、[[範例 - Playwright 網頁登入]]這兩篇，都需要行內環境把儲存空間、內部網域串接好才能真的跑完（目前卡在[[範例 - 探測 n8n 主機環境]]記錄的那兩個問題）。但「讓同事熟悉 n8n 操作」這件事不用等——這篇的三個練習**完全不連外部網路、不碰檔案系統**，只用 n8n 自己就能跑完，現在就能在行內環境練。

更重要的是：這三個練習不是白練的暖身操，而是[[開發規範 - RPA 對照版]]第 2 節骨架（讀取清單 → 逐筆處理 → 分支 → 彙總、錯誤處理）的縮小版。等 automation-api、內部系統串接都通了，同事只要把「假資料」換成「真的讀 Excel／呼叫 automation-api」，後面的分支、彙總、錯誤處理邏輯完全不用重學。

---

## 名詞對照表

| n8n 英文介面 | 繁體中文 | 說明 |
|---|---|---|
| Manual Trigger | 手動觸發 | 用按按鈕的方式啟動流程 |
| Code | 程式碼節點 | 這篇用來產生假資料、練習拋出錯誤 |
| IF | 條件判斷 | 依條件把資料分成兩條分支 |
| Edit Fields (Set) | 編輯欄位 | 新增或修改資料欄位 |
| Merge | 合併 | 把兩條分支的資料合併回同一條 |
| Form Trigger | 表單觸發 | 產生一個網頁表單當作流程起點 |
| Executions | 執行紀錄 | 左側選單，可以看每次執行的成功/失敗與詳細內容 |
| Continue On Fail | 失敗時繼續 | 節點設定選項，讓某個節點失敗後流程還能繼續往下走，而不是整個中斷 |

## 練習 1｜假資料批次處理（練骨架，最重要）

```
[Manual Trigger] → [Code：產生假清單] → [IF：金額<0？] ──True──→ [Set：標記異常] ──┐
                                                    └──False─→ [Set：標記已處理] ──┴→ [Merge] → [Code：彙總]
```

### Step 1｜建立 Workflow

1. **Workflows** → **+ New workflow**，命名「練習 - 假資料批次處理」
2. 加 **Manual Trigger**（手動觸發）

### Step 2｜Code 節點產生假資料

1. Manual Trigger 右側點 **「+」**，搜尋 `code`，加 **Code**（程式碼節點），語言選 **JavaScript**
2. 貼入：

   ```javascript
   return [
     { json: { 客戶編號: 'A001', 金額: 1000 } },
     { json: { 客戶編號: 'A002', 金額: -500 } },
     { json: { 客戶編號: 'A003', 金額: 2000 } },
   ];
   ```

   這一步是在模擬「原本要讀 Excel 或呼叫 automation-api 拿到的清單」，先用寫死的資料代替。

### Step 3｜IF 節點分支

1. Code 節點右側點 **「+」**，搜尋 `if`，加 **IF**（條件判斷）
2. 條件設定：左邊填 `{{ $json.金額 }}`，選 **smaller than**（小於），右邊填 `0`

### Step 4｜兩個分支各自加 Set 節點

1. IF 節點的 **True** 輸出右側點 **「+」**，加 **Edit Fields (Set)**（編輯欄位）：
   - 點 **Add field**，Name 填 `處理狀態`，Value 填 `異常`
2. IF 節點的 **False** 輸出右側點 **「+」**，加另一個 **Edit Fields (Set)**：
   - 點 **Add field**，Name 填 `處理狀態`，Value 填 `已處理`

### Step 5｜Merge 節點合併兩條分支

1. 加一個 **Merge**（合併）節點
2. 把兩個 Set 節點的輸出都接到這個 Merge 節點（滑鼠拖曳連線，Merge 節點左側會有兩個輸入點）
3. **Mode**（模式）選 **Append**（附加，把兩邊的資料接在一起，不是比對合併）

### Step 6｜最後加 Code 節點彙總

1. Merge 節點右側加另一個 **Code** 節點，貼入：

   ```javascript
   const items = $input.all();
   const 異常筆數 = items.filter(i => i.json.處理狀態 === '異常').length;

   return [{
     json: {
       總筆數: items.length,
       異常筆數: 異常筆數,
       已處理筆數: items.length - 異常筆數,
     }
   }];
   ```

2. 點 **Test workflow**，看最後這個 Code 節點的輸出，應該是：

   ```json
   { "總筆數": 3, "異常筆數": 1, "已處理筆數": 2 }
   ```

跟[[開發規範 - RPA 對照版]]第 2 節骨架對照：Step 2 是「②讀取待處理清單」，Step 3-5 是「③主流程逐筆處理＋分支」，Step 6 是「④結束作業彙總」——完整走過一次骨架，只是還沒接上真正的資料來源。

## 練習 2｜Form Trigger 收資料（不受網路限制影響）

Form Trigger 是**別人連進來**（inbound），跟 HTTP Request 節點**主動連出去**（outbound）方向相反。行內環境目前卡住的是 outbound（連不到內部系統、DNS 查不到），Form Trigger 完全不受影響，現在就能練，也直接是[[範例 - Excel 處理（取代 VBA）]]Step 1 會用到的節點。

### Step 1｜建立 Workflow

1. 新增 workflow，命名「練習 - 表單收資料」
2. 加 **Form Trigger**（表單觸發）：
   - **Form Title** 填 `同事資料練習`
   - 點 **Add Form Field**，**Field Label** 填 `你的名字`，**Field Type** 選 **Text**

### Step 2｜加 Set 節點整理資料

1. Form Trigger 右側加 **Edit Fields (Set)**（編輯欄位）
2. 點 **Add field**，Name 填 `打招呼訊息`，Value 填：

   ```
   {{ 'Hello, ' + $json['你的名字'] + '！' }}
   ```

### Step 3｜測試

1. 點 **Test workflow**，複製出現的 Test URL
2. 開新分頁貼上，填入名字，送出
3. 回到 n8n，點 Set 節點看輸出，確認 `打招呼訊息` 有正確組出來

## 練習 3｜故意製造錯誤，練 Execution History 除錯

### Step 1｜建立會失敗的 Workflow

1. 新增 workflow，命名「練習 - 錯誤處理練習」
2. 加 **Manual Trigger**
3. 右側加 **Code** 節點，貼入：

   ```javascript
   throw new Error('故意測試失敗，練習看錯誤畫面');
   ```

4. 點 **Test workflow**——這次會失敗，Code 節點上會出現紅色叉叉，這是預期中的結果

### Step 2｜看懂錯誤畫面

1. 點紅色叉叉的 Code 節點，右側會顯示錯誤訊息，就是你剛才寫的那句話
2. 左側選單點 **Executions**（執行紀錄），找到剛才那次失敗的執行，點進去——之後行內任何流程失敗，都是從這裡開始查

### Step 3（選用）｜讓流程失敗後還能繼續走，不整個中斷

1. 點 Code 節點，找節點設定面板裡的 **「On Error」**（或齒輪圖示裡的 Settings）選項，改成 **Continue**（繼續）

   > 不同版本 n8n 這個選項的位置可能不太一樣，通常在節點設定面板的 Settings 分頁裡

2. Code 節點右側加一個 **IF** 節點，條件設定：`{{ $json.error }}` **exists**（存在）
3. 重新 Test workflow，這次即使 Code 節點失敗，流程還是會繼續往 IF 節點走，可以在 True 分支接後續的通知或記錄動作

這一段對應[[開發規範 - RPA 對照版]]第 5.1 節的 GlobalErrorHandler 概念——差別是那邊是「整個 workflow 層級」的錯誤處理（Workflow Settings 裡指定 Error Workflow），這裡練的是「單一節點層級」的錯誤處理，兩個是互補的機制，不衝突。

---

## 小提醒

- 三個練習都建議在檔名前面統一加「練習 -」，方便跟正式的 workflow 分開管理，練習完可以直接刪除
- 練習 1 的 Merge 節點如果找不到，搜尋 `merge` 應該就有，是 n8n 核心節點，不會被行內環境限制
- 等[[範例 - 探測 n8n 主機環境]]裡記錄的儲存空間、內部網域問題被 IT 解決後，練習 1 的 Step 2（Code 節點產生假資料）直接換成 HTTP Request 呼叫 automation-api，其他節點原封不動就能接上真正的自動化
